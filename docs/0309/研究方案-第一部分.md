# 第一部分 研究方案
## ——要做什么、为什么做、打算怎么做

**项目名称：** 三餐管家  
**组别：** 小学高  
**项目类别：** 社会科学

## 1. 要做什么

本研究拟设计并实现一款面向老年术后家庭照护场景的 AI 应用——**“三餐管家”**。项目聚焦“术后饮食管理难、医嘱执行难、家庭协作难”三类问题，形成可持续使用的日常辅助工具。

### 1.1 研究目标
1. 建立低门槛记录机制：支持老人通过语音完成饮食与体征记录；
2. 建立医嘱数字化机制：支持家属通过拍照识别医嘱与药盒信息；
3. 建立建议生成机制：结合医嘱规则与当日记录生成下一餐建议。

### 1.2 预期成果
- 一个可运行的功能原型（语音记录、拍照识别、智能建议）；
- 一套围绕“老人—家属—系统”的家庭使用流程；
- 一份基于真实家庭场景的研究与实践总结。

---

## 2. 为什么做

### 2.1 问题来源
研究源于家庭真实照护经历：奶奶在胆囊切除术后，长期需要低脂、少盐、少糖饮食与规律用药。实际执行中出现了高频困难：
- 药物信息复杂，不易快速理解；
- 饮食原则抽象，不易落实到每一餐；
- 医嘱容易遗忘，执行连续性不足。

### 2.2 现实痛点
- 传统药盒只能提示时间，无法判断饮食或用药是否合规；
- 家庭成员依赖经验决策，标准不统一、误差较大；
- 医嘱、饮食记录与身体数据彼此割裂，难以形成闭环管理。

### 2.3 研究价值
1. **实践价值**：降低家庭照护沟通成本，提升日常执行效率；
2. **技术价值**：将语音识别、OCR 与规则推理整合到真实生活场景；
3. **教育价值**：体现“以问题为导向”的项目学习方法与创新实践能力；
4. **社会价值**：为更多术后老人家庭提供可复制的数字化照护思路。

---

## 3. 打算怎么做

### 3.1 研究思路
采用“**场景发现—需求拆解—原型开发—家庭验证—持续优化**”路径，先建立最小可用闭环，再逐步完善体验与功能。

### 3.2 功能设计与对应关系
- **语音记录模块**：解决老人不会打字、记录困难问题；
- **拍照识别模块**：解决医嘱与药盒信息读取困难问题；
- **智能建议模块**：解决“知道原则但不会落实到每餐”问题；
- **家庭协作模块**：明确“奶奶说、家属拍、系统记与提醒”的分工。

### 3.3 研究方法
1. **场景观察法**：从术后家庭照护中提取高频问题；
2. **原型开发法**：基于 Vibe Coding 快速构建可演示系统；
3. **迭代验证法**：通过家庭实际使用持续修正与优化。

### 3.4 可行性论证
- **技术可行**：语音转写、图像识别、规则推荐均有成熟实现路径；
- **资源可行**：依托家庭真实场景与已有设备即可开展测试；
- **时间可行**：按“核心功能优先”原则分阶段推进；
- **风险可控**：系统定位为辅助决策工具，不替代医生专业诊断。

### 3.5 阶段安排
- 阶段一：明确需求与关键场景（吃药、做饭、记录）；
- 阶段二：完成核心功能原型；
- 阶段三：进行家庭试用并采集反馈；
- 阶段四：优化功能表达并形成展示材料。

---

## 4. 本部分结论

本研究选题来自真实、高频且长期存在的家庭照护问题，具有明确应用需求；研究路径清晰、技术方案可落地、资源条件可满足，整体具备较高可行性与合理性，可进入后续实施与验证阶段。
