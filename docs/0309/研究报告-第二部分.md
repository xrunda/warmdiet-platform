# 第二部分 研究报告
## ——做了什么、怎么做的、发现了什么、结论是什么

**项目名称：** 三餐管家  
**组别：** 小学高  
**项目类别：** 社会科学

## 1. 做了什么（研究实施内容）

围绕奶奶术后家庭照护场景，本研究完成了“三餐管家”原型系统的设计与实践，重点完成以下工作：

1. **构建语音记录能力**  
   支持老人通过说话记录每日饮食与身体数据（如血压、餐次、食物类型）。

2. **构建拍照识别能力**  
   支持家属拍摄医嘱单、药盒和说明信息，系统自动提取关键饮食限制条件。

3. **构建饮食建议能力**  
   依据“医嘱规则 + 当日记录”输出下一餐建议，包括推荐食物、应避免食物及注意事项。

4. **构建家庭协作流程**  
   形成“奶奶说、家属拍、系统记与提醒”的稳定使用模式，降低家庭沟通和执行成本。

5. **完成多页面应用原型展示**  
   输出了可演示的 App 页面流程（登录、记录、识别、建议、查看等），支持研究展示与复盘。

---

## 2. 怎么做的（研究过程与方法）

本研究采用 **Vibe Coding（氛围编程）** 路线：以自然语言描述需求，快速生成原型，再通过真实使用持续迭代。

### 2.1 过程步骤

**步骤一：问题拆解**  
从家庭照护中识别高频问题：
- 记录难（老人输入困难）；
- 理解难（医嘱和药品信息复杂）；
- 执行难（每餐难以判断是否合规）。

**步骤二：功能映射**  
将问题一一映射为功能模块：
- 记录难 → 语音记录；
- 理解难 → 拍照识别；
- 执行难 → 智能建议。

**步骤三：原型实现**  
完成核心流程：
- 语音输入并结构化保存；
- 图片信息提取并更新规则；
- 结合规则与记录生成建议输出。

**步骤四：家庭场景验证**  
在真实家庭使用中反复试用，观察“是否会用、是否好懂、是否能执行”，并持续优化交互表达。

### 2.2 分工机制
- **项目发起者**：需求定义、流程设计、测试反馈整理；
- **家长**：技术环境与调试协助；
- **老师**：方法指导与研究逻辑把关。

---

## 3. 发现了什么（研究发现与分析）

### 3.1 核心发现

1. **语音是老人可持续使用的关键入口**  
   相比手动输入，语音明显降低了记录门槛，更符合老年人使用习惯。

2. **“拍照识别”能显著降低医嘱理解成本**  
   通过把复杂文字转换为可读规则，家庭成员更容易统一执行标准。

3. **建议必须“具体到一餐”才有执行力**  
   仅有“低脂少盐”原则不够，只有落实到“这顿吃什么、不吃什么”才能真正帮助决策。

4. **家庭协作比单点功能更重要**  
   项目价值不只在 AI 算法本身，更在于把“老人、家属、系统”组织成可持续协作流程。

### 3.2 过程中暴露的问题
- 方言、口语化表达可能影响识别准确性；
- 医嘱描述存在差异，规则提取需进一步标准化；
- 提醒方式仍有优化空间（频率、时机、表达方式）。

### 3.3 阶段性成效
- 原型已形成“记录—识别—建议”闭环；
- 家庭成员对流程理解更一致，日常执行更有依据；
- 项目从“想法”走向“可展示、可复用”的实践成果。

---

## 4. 结论是什么（研究结论与价值）

### 4.1 研究结论
本研究证明：在术后家庭照护场景中，将语音记录、拍照识别和规则建议进行组合，能够有效提升饮食管理的可执行性与连续性。“三餐管家”作为 AI 辅助工具具有现实可行性与应用价值。

### 4.2 成果价值
1. **应用价值**：帮助家庭把抽象医嘱落实到具体每餐决策；
2. **方法价值**：验证了“真实问题驱动 + 快速迭代”的项目研发路径；
3. **教育价值**：体现小学生在真实场景中进行技术创新与问题解决的能力；
4. **推广价值**：该模式可拓展到其他慢病/术后人群的家庭健康管理。

### 4.3 后续优化方向（与结论衔接）
- 增强方言识别能力；
- 补充术后饮食知识库和菜谱库；
- 优化提醒机制与家庭协同反馈闭环。
- 增加应用上架市场的产品设想，为更多有需要的家庭提供服务。
